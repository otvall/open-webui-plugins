# Domain docs

This repo uses a single-context layout: `CONTEXT.md` at the repo root
and ADRs under `docs/adr/`.

Before exploring code, read `CONTEXT.md` and ADRs relevant to the area.
If these files do not exist, proceed; the domain-modeling skill creates
them when terms or decisions are resolved.

Use glossary terms from `CONTEXT.md` in issues, proposals, hypotheses,
and tests. If a needed concept is absent, reconsider the term or note
the gap for domain modeling.

Surface any conflict with an existing ADR explicitly, naming the ADR
and why the decision may need to be revisited.
