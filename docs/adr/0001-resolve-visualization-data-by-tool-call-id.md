# Resolve visualization data by Native tool call ID

Open WebUI 0.11.1 exposes Native tool results in saved chat history, including an in-progress response stream. The PostgreSQL MCP tool cannot be changed, and regenerating thousands of JSON rows inside visualization HTML adds latency. Every `visualize` call therefore takes the SQL tool's exact `source_tool_call_id`. Its same-origin iframe reads the matching `function_call_output` through the authenticated chats API, and `getToolData()` returns a parsed JSON copy to arbitrary HTML/SVG code. The SQL result still enters the model's input context.

This choice binds the integration to saved chats, Native function calling, and iframe same-origin access. Missing, ambiguous, and non-JSON results fail visibly. We chose the chat API over DOM extraction because Open WebUI truncates long tool output in the rendered UI, and over separate storage because the MCP producer is outside this repo and cannot be modified. See the [chat API stream overlay](https://github.com/open-webui/open-webui/blob/v0.11.1/backend/open_webui/routers/chats.py#L57-L77) and [Native tool output format](https://github.com/open-webui/open-webui/blob/v0.11.1/backend/open_webui/utils/middleware.py#L5269-L5303).
